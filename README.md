# Factory Logic

Factory Logic — это инженерный справочник для диагностики промышленного оборудования.

Проект разрабатывается как портфолио Python Backend Developer и одновременно используется как рабочий инструмент для поиска информации по промышленному оборудованию.

На текущем этапе доступны два интерфейса:

- CLI
- MAX Bot

Оба используют одно общее бизнес-ядро приложения.

---

# Возможности

## Частотные приводы

### Allen-Bradley

#### PowerFlex 525

- поиск ошибки по коду;
- просмотр полного списка ошибок;
- параметры быстрого пуска (в разработке).

---

## Запчасти

### Bodymaker

- поиск по SAP-номеру;
- поиск по названию (в разработке).

# Архитектура

Проект построен по принципу разделения ответственности.

```
CLI
        │
        │
MAX Bot │
        ▼
+-------------------+
|     Services      |
+-------------------+
          │
          ▼
+-------------------+
|   Repositories    |
+-------------------+
          │
          ▼
+-------------------+
|      JSON Data    |
+-------------------+
```

Интерфейсы не работают с данными напрямую.

Вся бизнес-логика находится в сервисах.

Это позволяет использовать одно и то же ядро сразу из нескольких интерфейсов.

### Linux

**Создание виртуального окружения**

```bash
python3 -m venv .venv
```

**Активация виртуального окружения**

```bash
source .venv/bin/activate
```

**Установка зависимостей**

```bash
pip install -r requirements.txt
```

# Запуск CLI

```bash
python3 -m app.main
```

---

# Запуск MAX Bot

```bash
python3 -m app.interfaces.max_bot.main
```

---

# Запуск через Docker

Сборка образа:

```bash
docker compose build
```

Запуск:

```bash
docker compose up -d
```

Просмотр логов:

```bash
docker compose logs -f
```

Остановка:

```bash
docker compose down
```

# Реализованные интерфейсы

## CLI

Поддерживает:

- поиск ошибки;
- вывод полного списка ошибок;
- поиск запчастей.

---

## MAX Bot

Реализована кнопочная навигация.

Поддерживается:

- главное меню;
- меню частотных приводов;
- Allen-Bradley;
- PowerFlex 525;
- поиск ошибки;
- хранение пользовательского состояния во время поиска.

# Цель проекта

Проект создаётся как максимально приближённый к реальной коммерческой backend-разработке.

Основные цели:

- построение чистой архитектуры;
- разделение бизнес-логики и интерфейсов;
- возможность масштабирования на новые интерфейсы;
- использование в качестве рабочего инструмента инженера АСУТП.
